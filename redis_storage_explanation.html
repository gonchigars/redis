🎯 Level 1: Application Data Model (Your Diagram)

This is where your diagram fits - the logical organization of data types:

Hash: user:12345:profile → {name: "John", email: "john@example.com"} String: session:abc123 → "eyJhbGciOiJIUzI1NiIs..." List: activity:12345 → ["action1", "action2", "action3"] Set: permissions:12345 → {"read", "write", "admin"}
🔧 Level 2: Redis Data Structure Layer

Redis converts your logical structures into optimized internal representations:

Small Hash → ziplist (memory-efficient) Large Hash → hash table (fast access) Small List → ziplist or listpack Large List → quicklist (hybrid structure) Small Set → intset (if all integers) or hash table Large Set → hash table
🗂️ Level 3: Object Encoding Layer

Redis automatically chooses the most efficient encoding based on data size and type:

Strings: - RAW encoding: for strings > 44 bytes - EMBSTR encoding: for strings ≤ 44 bytes - INT encoding: for integer values Hashes: - ZIPLIST: when small (< 512 entries, < 64 bytes per value) - HASHTABLE: when large or contains big values Lists: - QUICKLIST: combination of ziplists for memory efficiency
💾 Level 4: Memory Management Layer

The lowest level - how Redis actually allocates memory:

jemalloc Memory Allocator: ├── Memory pools for different object sizes ├── Fragmentation management ├── Memory alignment optimization └── Garbage collection for expired keys Physical Memory Layout: [Object Header][Type Info][Expiration][Data Payload] 8 bytes 4 bytes 8 bytes Variable
